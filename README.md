## 1. 구성

| 파일 | 역할 |
|---|---|
| `main.py` | 엔트리포인트(오늘 읽기 → 변환 → 전송), `--dry-run` 지원 |
| `calendar_client.py` | Google Calendar 읽기(서비스계정, 읽기전용) |
| `transform.py` | **변환 규칙 전체**(장소약칭·출석/입회·머리말·기한) |
| `discord_sender.py` | 웹훅 전송(2000자 초과 시 분할) |
| `config/locations.yaml` | 기관 정식명칭 → 약칭 예외표 |
| `config/teams.yaml` | 팀별 변호사 명단(정변호사·수습) + 대표변호사 — 오후 팀별 알림 분류 기준 |
| `config/staff.yaml` | 변호사별 담당직원 명단 — 변호사별 `[휴무]` 칸 배정 기준 |
| `tests/test_transform.py` | 변환 회귀테스트 |
| `.github/workflows/daily.yml` | 매일 07:00 KST 전체 일정 알림([기한]/[일정]/[휴무] 3회) |
| `.github/workflows/evening.yml` | 매일 17:30 KST 익일 일정 팀별 알림(상담지원팀, 송무1·2팀) |
| `.github/workflows/ci.yml` | 푸시 시 자동 테스트 |

## 2. 변환 규칙 요약

- **머리말** `[의뢰인(장소약칭)]` — 사건번호 없는 일정은 생략하고 `시간 내용(장소)` 으로만 표기
- **장소 약칭**: `config/locations.yaml` 치환표에 있는 기관만 약칭으로 바꾸고, 없으면 원문 그대로 출력(자동 축약 없음)
  - 약칭이 필요한 기관은 `config/locations.yaml` 에 `정식명칭: 약칭` 한 줄 추가
  - 자사 사무소도 같은 표로 통일: `구분` 값이 `아스테리움`·`1006호`·`서울사무소` 등이면 `서울 1006호`,
    `학익동`·`인천` 등이면 `인천사무소` 로 정규화(별칭 추가/수정은 `locations.yaml`에서)
- **상담/미팅(`[회의]`)**: `[회의] (구분) [의뢰인]내용` → `[의뢰인] 내용 > 담당변호사` 으로 재구성하고
  `[회의]`·`(구분)` 군더더기는 제거. 장소(`구분`)와 의뢰인 전화(`이름(전화)`)를 아랫줄에 표기
  - 전화는 `의뢰인연락처` 필드 우선, 없으면 설명 맨 윗줄의 번호만 적힌 줄에서 인식
- **접견**: 제목·설명에 `…구치소`/`…교도소` 이름이 있으면 그 기관을 장소 아랫줄로 표기(없으면 생략).
  제목 괄호 `(서울남부교도소)` 처럼 중복되면 괄호 표기는 제거
  - 설명에 접견 예약번호(`스마트접견예약번호` 등 `접견`+`번호`가 든 필드)가 있으면 `접견번호 : …` 아랫줄로 표기
- **출석/입회**: 경찰·검찰 → `입회`, 법원 → `출석`
  - `출석변호사:` 의 `▲지정자` 만 실제 출석자(괄호 `(담당:…)` 는 무시)
  - 지정자 없으면 `미입회/미출석`, 출석변호사 줄 자체가 없으면 생략
- **변호사 표기**: 실명 그대로(약칭·`님` 없이). 예: `> 이돈호`, `> 김태환, 신이나`
- **섹션 구조**: 위에서부터 `[기한]`(종일 제출기한·불변기일 등) → `[일정]`(그 외 일정) → `[휴무]`(휴가·반차·연차 등 부재)
  - `[일정]` 라벨은 일정이 있으면 항상 표시. 휴가/반차/반반차/휴무/연차는 제목 키워드로 골라 맨 아래 `[휴무]`에 모음
- **비고 노출**: `비고:` 에 내용이 있으면 **필터 없이 그대로** 맨 아랫줄에 `비고 : 원문` 으로 표시
  (장소·연락처 줄보다 아래). 예: 상소제기 불변기일의 `비고: 항소X` → `비고 : 항소X`
  - ⚠️ 비고 칸 내용이 **그대로 알림에 나가므로** 사건번호·개인정보 등 민감정보는 비고에 적지 말 것
- **선고기일 대리출석 일원화**: 선고기일에 한해 출석변호사의 `복대리·청취대리·선고청취대리·선고청취` 표기를 모두 `청취대리`로 통일(다른 기일종류는 원문 유지)
- **발송**: 오늘 일정만, 주말·공휴일 포함 매일. 0건이면 `오늘 일정 없음`

### 오전 전체 알림 3분할 (07:00)

팀 구분 없이 보내는 것은 그대로이고, 한 통에 몰려 있던 세 섹션을 **각각 한 통씩** 보낸다.

- 머리말은 `📅 260810 월요일 [기한]` 형태 — 섹션명이 머리말에 붙는다
- 순서는 `[기한]` → `[일정]` → `[휴무]`, 해당 섹션이 비어도 `없음` 으로 발송
- `@everyone` 은 `[일정]` 한 통에만 (알림 3연타 방지). 바꾸려면 `main.py` 의
  `MORNING_MENTION_SECTION` 수정

### 팀별 오후 알림 분류 규칙 (`config/teams.yaml`, `config/staff.yaml`)

오후 17:30 익일 알림은 **상담지원팀(이돈호) → 송무1팀 → 송무2팀** 순 3회 발송하고,
각 팀 메시지 안에서 다시 **변호사별 섹션**으로 나눈다.
담당직원 태그(`#송무n팀`)는 Lawware에서 삭제 예정이라 쓰지 않고, **담당변호사 소속 팀**으로 나눈다.

**① 어느 팀 메시지에 실릴지 (`teams.yaml`)**

- **송무1/2팀**: 일정의 담당변호사(정식 기일은 `담당변호사:`, 그 외 일정은 `담당(변호사):`)가
  `teams.yaml` 의 `변호사`(정변호사) 명단에 있으면 그 팀에 포함.
  - 담당변호사 중 정변호사가 **하나도 없을 때만** `수습` 명단으로 폴백 판정
  - 서로 다른 팀 변호사가 함께 담당이면 **양쪽 팀 모두** 알림
  - **교차출석 팔로우**: 다른 팀 사건이라도 출석변호사가 우리 팀 정변호사면 우리 팀 알림에도 포함
  - 휴가·연차 등 휴무 일정은 제목의 이름(정+수습)으로 팀 판정
- **상담지원팀**: `#상담지원팀` 태그가 있거나, 이돈호 변호사가 담당/출석하는 일정
- **대표변호사**(`teams.yaml` 의 `대표변호사: [이돈호]`): 이 변호사의 섹션은 송무1·2팀 메시지
  **맨 위에 항상** 함께 실린다. 본인 소속 팀(상담지원팀) 메시지에는 중복 없이 한 번만.
- 담당변호사가 없거나 명단 밖(운영팀 자체 일정 등)이면 오후 팀 알림에는 미포함(오전 전체 알림에는 나감)

**② 팀 안에서 어느 변호사 섹션에 실릴지**

메시지는 `# ○○ 변호사` 아래에 그 변호사의 `[기한]`/`[일정]`/`[휴무]` 세 칸을 두는 구조다.
정변호사·수습변호사 모두 각자 섹션을 가지며, 일정이 없어도 세 칸을 그대로 보여준다.

- **일정**: 담당변호사 + 출석변호사(교차출석). 공동담당이면 **담당 변호사 섹션에 모두** 실린다
- **휴무**: 변호사 본인의 휴무 + `staff.yaml` 에 적힌 **담당직원의 휴무**.
  판정은 휴무 일정 **제목의 이름**으로 하며, 한 직원이 여러 변호사의 담당이면 그 변호사들
  섹션에 모두 실린다 (예: `우서영 연차` → 박준호·김정아·신이나·이하영 섹션에 모두)
- **`# 기타`**: 어느 변호사에도 배정되지 않지만 그 팀 알림 대상인 일정(공용 일정 등)을
  맨 아래에 모은다. 내용이 있을 때만 표시
- 금요일 저녁 토·일·월 묶음은 3일치라 길어지므로, **묶음에 한해** 일정 없는 변호사 섹션은 생략

**③ 인사이동 시**: 팀 소속은 `config/teams.yaml`, 담당직원은 `config/staff.yaml` 만 수정하면
전체에 반영된다. (두 파일의 명단이 어긋나면 회귀테스트가 잡아준다)

자세한 명세는 `transform.py` 상단 주석과 `tests/test_transform.py` 참고.

## 3. 최초 설정 (사무실에서 1회)

### 3-1. Google Calendar 읽기 권한 (서비스 계정)
1. [Google Cloud Console](https://console.cloud.google.com) 접속 → 새 프로젝트 생성
2. **API 및 서비스 → 라이브러리** → `Google Calendar API` **사용 설정**
3. **API 및 서비스 → 사용자 인증 정보 → 서비스 계정 만들기**
4. 만든 서비스 계정 → **키 → 키 추가 → JSON** → 키 파일(.json) 다운로드
5. 서비스 계정 이메일(예: `bot@PROJECT.iam.gserviceaccount.com`) 복사
6. **대상 Google 캘린더 설정 → 특정 사용자와 공유** → 위 이메일을 추가, 권한은
   **"모든 일정 세부정보 보기(읽기 전용)"**
   - ⚠️ **읽으려는 캘린더가 여러 개면, 각 캘린더마다 이 공유를 똑같이 해줘야** 합니다.
     하나라도 공유를 빠뜨리면 그 캘린더는 일정이 안 읽힙니다.
7. 같은 캘린더 설정 화면의 **"캘린더 통합 → 캘린더 ID"** 복사 (`...@group.calendar.google.com`)
   - 여러 캘린더를 합쳐 발송하려면 ID들을 **쉼표(,)로 이어** 한 줄로 만든다.

### 3-2. Discord 웹훅
1. 발송할 **비공개 채널** → 채널 설정 → **연동(Integrations) → 웹훅 → 새 웹훅**
2. 이름 지정 후 **웹훅 URL 복사**
3. 🔒 해당 채널/서버는 **외부 초대·검색 차단, 사무실 구성원만 접근**하도록 권한을 잠글 것
   (의뢰인 실명·사건명이 표시되므로 비밀유지상 필수)

### 3-3. GitHub 저장소 + Secrets (자동 실행용)
1. GitHub 비공개 저장소 생성 → 이 폴더의 파일 전부 업로드
2. 저장소 **Settings → Secrets and variables → Actions → New repository secret** 으로 등록:
   - `GOOGLE_SERVICE_ACCOUNT_JSON` : 3-1에서 받은 JSON **파일 내용 전체**
   - `GOOGLE_CALENDAR_ID` : 캘린더 ID (여러 개면 쉼표/줄바꿈으로 구분해 모두 입력)
   - `GOOGLE_SERVICE_ACCOUNT_JSON_2` / `GOOGLE_CALENDAR_ID_2` : 두 번째 구글 계정의 키·캘린더 ID (계정이 하나면 생략)
   - `DISCORD_WEBHOOK_URL` : 기본(오전 전체 알림) 채널 웹훅 URL
   - `DISCORD_WEBHOOK_URL_SONGMU1` / `_SONGMU2` / `_SANGDAM` : 오후 팀별 채널 웹훅
     (미설정 시 해당 팀 알림은 기본 채널로 폴백)
3. **Actions** 탭에서 워크플로 활성화

이후 매일 07:00(KST)에 `daily.yml` 이 자동 실행됩니다.
즉시 테스트하려면 Actions → `daily-schedule-notify` → **Run workflow**(수동 실행).

## 4. 로컬 테스트

```powershell
# 의존성 설치
python -m pip install -r requirements.txt

# 변환 회귀테스트 (계정 없이도 실행 가능)
python tests/test_transform.py

# 실제 캘린더로 변환 결과만 미리보기(전송 안 함)
$env:GOOGLE_SERVICE_ACCOUNT_JSON = Get-Content key.json -Raw
$env:GOOGLE_CALENDAR_ID = "...@group.calendar.google.com"
python main.py --dry-run
```

> Windows 로컬 실행 시 `tzdata` 패키지가 필요합니다(`requirements.txt` 에 포함).

## 5. 운영/유지보수 메모

- **장소 약칭이 어색하게 나올 때**: `config/locations.yaml` 에
  한 줄 추가/수정 후 커밋하면 다음 발송부터 반영.
- **발송 시각 변경**: 실제 트리거는 **cron-job.org** 이므로 그곳의 작업 스케줄을 수정
  (워크플로의 `schedule:` cron은 백업용 주석 — [`외부-스케줄러-설정.md`](docs/외부-스케줄러-설정.md) 참고).
- **인사이동(변호사 팀 이동·입퇴사)**: `config/teams.yaml` 수정 → 팀 분류에 반영.
- **직원 담당 변경(변호사별 주담당·부담당)**: `config/staff.yaml` 수정 → 변호사별 `[휴무]` 칸에 반영.
  - 팀 명단에 있는 변호사가 `staff.yaml` 에 빠져 있으면 `python tests/test_transform.py` 가 실패한다.
- **실데이터 검증 권장**: 운영 전 하루치 실제 일정으로 `--dry-run` 결과를 눈으로 대조하여
  약칭·입회/출석·기한 분기가 의도대로 나오는지 확인.

- 서비스계정 키(.json)와 `.env` 는 **절대 커밋 금지** (`.gitignore` 로 제외됨).
- 비밀값은 **GitHub Secrets** 로만 보관.
- 메시지에는 의뢰인 실명·연락처·기일 정보가 포함되고, **비고 칸 내용도 필터 없이 그대로** 발송된다.
  - 따라서 발송 채널은 반드시 **사무실 전용(외부 초대·검색 차단)** 으로 잠글 것(§3-2).
  - 비고에 노출되면 안 되는 메모(내부용 코멘트 등)는 적지 말 것 — 그대로 알림에 나간다.
